# 아이디어 — 제3회 ○○시 열린데이터 생활문제 해결 아이디어 공모전

> **점수는 모델의 자기추정이다.** 심사위원 점수가 아니다. 순위를 참고하되 최종 선택은 사람이 한다.
> 배점은 `rubric.md`를 그대로 옮겼다: 창의성 30 / 실현가능성 25 / 기대효과 25 / 완성도 20.

## 발산 12개 (4축 × 3)

**데이터 주도**
- `01` 소음지도 — 민원 데이터와 공사 인허가 데이터를 겹쳐 소음 발생을 사전 예고
- `02` 빈 주차면 예보 — 주차장 실시간 데이터로 도착 시점의 여유를 예측
- `03` 침수 취약 골목 — 강우·배수 민원·고도 데이터 결합으로 위험 구간 표시

**사용자 경험**
- `04` 민원 번역기 — 행정 용어 민원 답변을 생활 언어로 바꿔 설명
- `05` 우리동네 공사 달력 — 흩어진 공사 공고를 주소 기준 한 화면으로
- `06` 복지 자격 역질문 — 조건을 묻는 대신 상황을 말하면 받을 수 있는 제도를 찾아줌

**업무 자동화**
- `07` 중복 민원 묶음 — 같은 사안의 민원을 자동 군집화해 담당 부서에 한 건으로
- `08` 시설 점검 우선순위 — 노후도·이용량·민원 이력으로 점검 순서 산출
- `09` 공고문 요약 배포 — 시 공고를 자동 요약해 대상자 채널로 분류 발송

**사각지대**
- `10` 야간 보행 취약 구간 — 가로등 고장 신고와 보행 사고 데이터 교차
- `11` 이동약자 경로 — 경사·턱·엘리베이터 고장 정보를 반영한 실시간 경로
- `12` 1인 가구 폐기물 — 대형폐기물 배출 절차를 사진 한 장으로 대행 신청

## 상위 3개 견적서

### [06] 복지 자격 역질문

- **프레임 전환** — "제도를 찾는 시민"에서 "시민을 찾아가는 제도"로
- **핵심 모듈** ① 상황 서술 → 조건 구조화 ② 제도 매칭·자격 판정 ③ 미신청 사유 추적
- **데모 한 장면** — "작년에 남편이 아파서 일을 못 했어요"라고 쓰면 받을 수 있었던 제도 3개와 신청 마감일이 뜬다
- **차별점** — 기존 복지로·시 홈페이지는 제도명을 알아야 검색된다. 여기는 상황에서 출발한다
- ⚠ **최대 약점** — 자격 판정을 틀리면 피해가 크다. "안내일 뿐"이라고 면책하면 기대효과가 깎이고, 확정 판정을 하면 실현가능성이 깎인다. → 판정 대신 **가능성 등급 + 확인처 연결**로 설계하면 방어된다
- 구현 난이도: 중 — 제도 데이터 정형화가 대부분의 공수

### [11] 이동약자 경로

- **프레임 전환** — "가장 빠른 길"에서 "실제로 갈 수 있는 길"로
- **핵심 모듈** ① 경사·턱 데이터 지도 매핑 ② 엘리베이터 고장 실시간 반영 ③ 사용자 제보
- **데모 한 장면** — 같은 출발·도착지에서 일반 경로와 이동약자 경로가 갈라지고, 일반 경로에 계단 3개가 있다고 표시된다
- **차별점** — 기존 지도 앱은 엘리베이터 고장을 모른다. 실시간 고장 데이터가 차별점의 전부다
- ⚠ **최대 약점** — 그 실시간 데이터가 ○○시에 실제로 개방돼 있는지 확인 안 됨. **없으면 아이디어가 성립하지 않는다.** 선택 전에 반드시 확인
- 구현 난이도: 상 — 데이터 확보 여부에 전부 걸려 있음

### [03] 침수 취약 골목

- **프레임 전환** — "비 온 뒤 신고"에서 "비 오기 전 표시"로
- **핵심 모듈** ① 배수 민원·고도·강우 결합 위험도 ② 골목 단위 지도 ③ 강우 예보 연동 알림
- **데모 한 장면** — 예보 진입 시 위험 골목이 순차로 켜지고, 실제 작년 침수 신고 위치와 겹쳐 보인다
- **차별점** — 시 재난 문자는 구역 단위, 이건 골목 단위
- ⚠ **최대 약점** — "예측이 맞느냐"를 증명할 방법이 기획서 단계에서 없다. 과거 데이터로 사후 검증 결과를 제시하지 않으면 기대효과 점수가 안 나온다
- 구현 난이도: 중
