# 루브릭 프리셋 — AI Nativeness

**출처: 프리셋(추정).** 요강에 명시된 기준이 있으면 그것이 우선이며, 프리셋은 빈칸만 메운다. `rubric.md`에 `출처=프리셋(추정)`으로 표시한다.

적용 대상: 결과물이 아니라 **참가자의 AI 활용 과정 자체를 채점**하는 대회·평가. 현장에서 과제를 받고, 심사자가 코드·커밋·대화 로그를 직접 읽어 문서와 실제 산출물이 연결되는지 대조하는 형식. 채용 연계 평가에서 늘고 있는 형태다.

---

## 3+1축 구조

배점은 축당 100점 균등을 기본으로 한다. 실제 대회의 배점이 공개되면 그것으로 덮어쓴다.

### ① 기술 관리 (Technique)

> AI가 만든 산출물을 본인이 직접 장악해서, 실제로 돌아가게 만들고, 유지 가능한 구조로 짜고, 보안이 새지 않게 구성했는가?

| 세부 항목 | 무엇을 보면 점수가 나오는가 |
|---|---|
| 코드 유지보수성 | 구조가 읽히는가, 중복·죽은 코드가 없는가 |
| 요구사항 충족도 | 과제가 요구한 것을 실제로 다 했는가 |
| 기능적 정확성 | 돌려보면 되는가, 엣지 케이스에서 깨지지 않는가 |
| 실무 품질 위험 | 보안·에러 처리·입력 검증 |
| 제출물 완성도 | 실행 가능한 상태로 제출되었는가 |

### ② 의도 관리 (Intent)

> AI에게 일을 맡기고 조향하며, 목표와 제약을 정의하고 작업을 분해해 위임하고, 검증 루프로 결과를 통제했는가?

| 세부 항목 | 증거가 어디에 남는가 |
|---|---|
| Output 목표 구체화 | `INTENT.md` 목표·수용기준 |
| 재사용 가능한 작업 체계 구축 | 스크립트·템플릿·반복 절차 |
| 의도 갱신 및 맥락 유지 | `INTENT.md` 의도 갱신 로그 |
| 검증 루프 설계 및 통제 | `verification.log`, 실패→수정→재검증 흔적 |
| 문제 상황 및 제약 정의 | `INTENT.md` 제약·비목표 |
| 작업 분해·위임 설계 | 작업 분해 트리, 핸드오프 단위 |

이 축은 참가자 간 점수 차가 가장 크게 벌어지는 구간이다.

### ③ 인지 관리 (Cognition)

> AI의 작업과 산출물을 이해하고, 왜 이 구조인지·어떻게 동작하는지·어디서 깨지는지를 본인 산출물 기준으로 설명할 수 있는가?

| 세부 항목 | 증거 |
|---|---|
| AI 산출물 동작 및 리스크 예측 | `COGNITION.md` 예상 리스크 표 |
| AI 산출물 구조 이해 | 구조 설명 + 파일·줄 단위 지목 |
| AI 의사결정 및 근거 이해 | AI 제안을 받아들인/거부한 이유 |

**대체로 가장 점수가 낮게 나오는 축이다.** 채우면 바로 벌어진다.

### ④ 소통 (Communication) — 트랙에 따라 적용

> 다른 사람 혹은 다른 세션이 자연스럽게 이어갈 수 있게 작업했는가.

인수인계 문서를 남긴 참가자가 유리하다.

---

## 이 유형의 채점 방식

- 심사자(사람 또는 AI)가 **코드·커밋·대화 로그를 직접 읽는다.**
- 항목마다 충족·부분충족 판정과 증거 좌표를 남긴다.
- **문서에 적힌 것과 실제 코드·커밋이 연결되는지 대조한다.** → 문서를 나중에 몰아서 쓰면 어긋나서 걸린다.
- 제출 후 확인 문제(구술·서술)가 붙는 경우가 많고, 모범 답안이 3단계 구조로 채점된다.

## 확인 문제 답변 3단계

1. 내 코드의 **구체적 약점 지점 지목**
2. 그게 **왜 위험한지 파급 설명**
3. **다음에 뭘 검증·개선할지 계획**

모든 답변을 이 순서로 고정한다. `COGNITION.md`의 리스크 표가 그대로 재료가 된다.

## 이 루브릭이 파이프라인에 강제하는 것

- `②ideate` 건너뜀 — 현장에서 과제를 받으므로 발상할 것이 없다. `①recon`은 경량으로 수행한다(대회명·일정·트랙·심사방식).
- 증거 5축(`INTENT.md` / 커밋 규약 / `verification.log` / `COGNITION.md` / `SESSION-HANDOFF.md`)을 **작업 시작 시점에** 만들고 진행하며 갱신. 위치는 제출 레포 루트.
- 작게 자주 커밋. 커밋 본문에 `why / 제약 / 검증`.
- 주기적 자가점검으로 빈 축 경고.
- `④report`를 쓰지 않는다.
