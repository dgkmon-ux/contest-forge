# 루브릭 프리셋 — 해커톤

**출처: 프리셋(추정).** 요강에 명시된 기준이 있으면 그것이 우선이며, 프리셋은 빈칸만 메운다. `rubric.md`에 `출처=프리셋(추정)`으로 표시한다.

적용 대상: 기간 내 개발해 **작동하는 결과물**을 제출하는 대회 (기업·기관 주최 개발 해커톤 등).

> 참가자의 AI 활용 과정 자체를 채점한다면 이 프리셋이 아니라 `ai-nativeness.md`를 쓴다.

기상청·공공기관·금융사 주최 대회는 이것이 숨은 가점이 아니라 **명시 배점**인 경우가 많다. 요강에 없어도 심사위원 구성상 실질 가중치가 붙는다. 이 항목을 추가하면 1·2번 배점을 5씩 낮춘다.

## 이 유형에서 실제로 당락을 가르는 것

- **5분 안에 돌아가야 한다.** 환경 구축이 복잡하면 심사위원은 안 돌려본다. README 3줄, 시드 데이터 포함, 원커맨드 실행.
- **주최사 데이터를 썼는가.** 기관 주최 해커톤은 자체 데이터·API 활용률이 사실상 별도 가점이다. 요강에 없어도 그렇다.
- **시연 중 실패 대비.** 라이브 데모가 죽을 경우를 대비해 녹화 영상 또는 재생 가능한 시나리오 스크립트를 준비한다.
- **범위를 좁힌 팀이 이긴다.** 기능 5개를 반쯤 만든 팀보다 2개를 끝까지 만든 팀이 완성도 30점을 가져간다.

## 감점 요인

- 제출 시점에 빌드가 깨져 있음
- 실제 개인정보·무단 수집 데이터 사용
- 외부 유료 API 의존으로 심사위원이 실행 불가
- 발표 시간 초과
