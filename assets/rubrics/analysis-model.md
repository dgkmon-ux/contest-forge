## 이 유형에서 실제로 당락을 가르는 것

- **"활용 예정"은 0점이다.** 데이터 목록만 있고 실제 수집·학습 결과가 없으면 항목 2가 통째로 날아간다. 이 유형에서 가장 흔한 탈락 원인이다.
- **기준모델 비교가 없으면 성능 주장이 성립하지 않는다.** 단순 기준(직전값·전년 동기값·최빈값·평균)을 반드시 함께 내고, **못 이긴 항목은 못 이겼다고 쓴다.** 정직한 실패 보고는 감점이 아니라 신뢰 근거다.
- **상관을 인과로 쓰면 논리 배점에서 무너진다.** 예측·시나리오·변수 기여도(SHAP 등)를 정책 효과로 서술하지 않는다. 발표 질의응답에서 가장 먼저 찔리는 곳이다.
- **라벨(정답값)을 만들 수 있는가가 실현 가능성의 전부다.** 사람이 새로 표기해야 하는 라벨은 대회 기간에 확보되지 않는 경우가 많다. 특히 "전문가 N명이 독립 평가"류는 팀 정원과 충돌하는지 확인한다 — 팀원이 평가하면 자기채점이고 검증이 무효가 된다.
- **외부 승인이 필요한 데이터는 필수 경로에 넣지 않는다.** 마이크로데이터 이용신청, 기관 협약, 심의는 대회 기간 안에 안 나온다. 공개 API·포털로 대체 경로를 만든다.
- **시각화 산출물이 별도 제출물이면 그것이 항목 2의 그릇이다.** 규격(확장자·정적/대화형)을 반드시 확인한다. 기획서 안의 그림으로 대체되는지 모른 채 만들면 규격 위반이다.

## 감점 요인

- 분량·양식 위반
- 데이터 출처·기간·공간단위 미표기
- 공간·기간·집계기준이 다른 자료를 정합성 처리 없이 결합
- 무작위 분할로 시계열·공간 데이터를 학습·검증 분리 (누수)
- 기능이 병렬 나열되고 코어 모델이 무엇인지 한 문장으로 답할 수 없음
- 대상이 "전 국민", "모든 시민"처럼 넓음
- 요강이 금지한 데이터(무단 수집·라이선스 미확인 민간 유료) 사용
- 블라인드 심사에서 소속·이름 노출

## 발표 심사가 있는 경우

이 유형은 서면 통과 후 발표 배점에서 **논리성**과 **전달력**이 절반을 넘는 경우가 많다. 아이디어가 아니라 준비물이 결정한다.

- 심사위원의 반박을 **먼저 말하고 답하는** 구조로 짠다
- 검증 결과 슬라이드를 반드시 넣는다 — 기준모델 표, 누수 방지 설계, 반례
- 한계와 사람 승인 단계를 스스로 밝힌다. 이것이 논리성 점수를 지킨다
