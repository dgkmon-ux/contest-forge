# ① recon — 요강 구조화와 심사표 확정

목표: 사용자가 준 요강 원문을 `brief.md`와 `rubric.md` 두 파일로 정규화한다. 이후 모든 단계가 이 두 파일만 참조한다.

---

## 1. 원문 확보

SKILL.md §3에 따라 사용자에게 요강 전문/파일을 요청한다. 자동 수집하지 않는다.

받은 자료가 여러 개(웹 본문 + 첨부 PDF + FAQ + 온라인 폼 스크린샷)면 전부 읽고 하나로 합친다. 서로 어긋나면 **더 늦게 나온 자료 / 공식 첨부**를 우선하고, 충돌 사실을 brief.md 하단에 기록한다.

`.hwp`는 읽을 수 없다. PDF 변환 또는 붙여넣기를 요청한다.

---

## 2. brief.md 필수 항목 12

아래를 표로 채운다. **모르는 것은 지어내지 말고 `[미확인]`**으로 둔다.

### 미확인은 두 종류다 — 반드시 구분한다

| 표기 | 뜻 | 다음 행동 |
|---|---|---|
| `[미확인 — 미탐색]` | 자료를 아직 다 못 봤다 | **내가 더 찾는다.** 첨부·FAQ·지난 회차 공고 |
| `[미확인 — 자료에 없음]` | 공식 자료 전체를 봤는데 그 항목이 아예 없다 | **주최·운영사에 문의한다.** 내가 더 찾아도 안 나온다 |

이 구분이 없으면 게이트가 무력해진다. 국내 공모전, 특히 기관·지자체 주최는 **지식재산 귀속, 중복 수상 제한, 제출물 분량 규격을 요강에 아예 안 쓰는 경우가 흔하다.** 이때 `[미확인]` 하나로 뭉뚱그리면 게이트가 영원히 막히고 매번 강제통과가 되어, 게이트가 있으나 마나 해진다.

**판정 방법:** 확보한 모든 소스(웹 본문 + 첨부 + FAQ + 지난 회차)를 다 읽은 뒤에만 `자료에 없음`을 붙인다. 한 소스만 보고 붙이지 않는다.

```markdown
# <공모전명>

| 항목 | 내용 |
|---|---|
| 주최·주관 | |
| 유형 | idea-contest / hackathon / startup-grant / ai-nativeness |
| 주제·트랙 | |
| 참가자격 | |
| 팀 구성 제한 | |
| 접수 마감 | YYYY-MM-DD (시각 포함) |
| 전체 일정 | 접수 → 1차 → 본선 → 발표 |
| 제출물 목록 | 문서/PPT/영상/코드 — 있는 것만 |
| **제출 규격** | 분량·형식·양식파일·파일명 규칙 |
| **발표** | 유/무 · 발표 시간 · 형식(대면/영상/서류만) |
| **시연 영상** | 필요 여부 · 길이 제한 |
| 시상 규모 | |
| 심사 방식 | 서류/발표/현장구현/블라인드 |
| 지식재산·활용 조건 | |

## 요강 원문에서 그대로 옮긴 핵심 문장
> (주제 정의, 심사 관점, 금지사항 등 해석 없이 인용)

## 미확인 항목
- [미확인] ...

## 자료 출처
- 사용자 붙여넣기 / <파일경로> / <URL>
```

**제출 규격은 특히 집요하게 확보한다.** ④단계에서 분량 초과·양식 미준수로 탈락하는 일이 실제로 자주 생긴다. A4 몇 장인지, PPT 몇 장인지, 지정 양식 파일이 있는지, 동영상이 필요한지.

## 3. rubric.md — 심사표 정규화

`assets/rubrics/<유형>.md`를 프리셋으로 열고, 요강에 명시된 기준을 덮어쓴다.

```markdown
# 심사표 — <공모전명>

| # | 항목 | 배점 | 출처 | 근거 문구 |
|---|---|---|---|---|
| 1 | <요강 또는 프리셋의 항목명> | <배점> | 요강 / 프리셋(추정) | "<요강 원문 인용>" |
| 2 | ... | | | |

## 항목별 득점 조건
- **창의성** — 무엇을 보여주면 이 점수를 받는가 (구체적으로)
- ...

## 감점·탈락 조건
- 요강에 명시된 금지사항
- 제출 규격 위반

## 심사 방식이 강제하는 것
(예: 블라인드 심사 → 소속·개인정보 노출 금지 / 현장 시연 → 오프라인 동작 필수)
```

- 요강에 배점이 없으면 프리셋 배점을 쓰되 `출처=프리셋(추정)`으로 반드시 표기한다.
- 배점 합이 100이 아니어도 프리셋을 억지로 맞추지 않는다 (ai-nativeness는 300+α).
- **"항목별 득점 조건"이 이 파일의 진짜 알맹이다.** 항목명만 옮겨 적으면 ②단계 채점이 공허해진다.

> **요강 배점을 쓰더라도 프리셋을 덮어쓰고 끝내지 않는다.**
> 프리셋의 배점은 버려도, **「이 유형에서 실제로 당락을 가르는 것」과 「감점 요인」은 배점표와 무관하게 성립한다.** 프리셋 파일을 끝까지 읽고, 해당하는 항목을 요강의 심사항목에 매핑해 「항목별 득점 조건」에 녹인다. 어느 프리셋 줄에서 왔는지는 적지 않아도 되지만, **한 줄도 옮기지 않았다면 프리셋을 안 읽은 것이다.**

### 심사 단계가 둘 이상이면 (예선 서면 + 본선 발표)

배점표를 단계별로 **각각** 만든다. 합치거나 평균 내지 않는다. 그리고 어느 배점표로 ②단계 아이디어를 채점할지 정한다.

- 기본값은 **1차(서면) 배점**이다. 1차를 통과하지 못하면 본선 배점은 의미가 없다.
- 본선에만 있는 항목(발표 전달력 등)은 아이디어의 속성이 아니라 준비물의 속성이므로 아이디어 채점에 넣지 않는다. 대신 `rubric.md`에 "④단계에서 이 항목이 배점의 N%"라고 남긴다.

## 4. 게이트 🚧

다음 중 하나라도 `[미확인]`이면 ②로 진행하지 않는다.

**진행 가능 여부 — 여기서 걸리면 준비 자체가 무의미하다**
- 참가 자격 (학적·연령·소속·창업 여부 등)
- 팀 구성 제한 (인원 상한, 1인 참가 가능 여부, 중복 팀 금지)
- 중복 수상·기출품 제한 (다른 대회 수상작·기제출작 사용 가능 여부)
- 지식재산 귀속·활용 조건

**작업 범위 결정**
- 접수 마감
- 주제·트랙
- 제출물 목록
- 제출 규격

앞 4개는 단순 미확인이 아니라 **자격 미달로 확인된 경우 즉시 중단하고 사용자에게 알린다.** 참가할 수 없는 대회를 끝까지 준비하는 것이 이 스킬의 최악의 실패다. IP 조건은 특히 놓치기 쉬운데, 출품작 권리가 주최사에 귀속되는 대회가 있다 — 창업으로 이어갈 아이디어면 사용자가 알고 결정해야 한다.

### 통과 판정 — §2의 두 종류에 따라 갈린다

| 상태 | 판정 |
|---|---|
| 전부 확인됨 | **통과** |
| `[미확인 — 미탐색]`이 남아 있음 | **차단.** 내가 더 찾는다. 못 찾으면 사용자에게 자료를 요청한다 |
| `[미확인 — 자료에 없음]`만 남아 있음 | **조건부 통과.** 아래 조건을 채우면 ②로 간다 |

**조건부 통과의 조건 — 셋 다 채워야 한다.**

1. `assets/inquiry-template.md`로 문의문을 만들어 사용자에게 제시했다 (연락처가 요강에 있으면 함께)
2. 각 항목이 **막혔을 때 무엇이 틀어지는지**를 한 줄로 적었다 — 예: "제출 분량 미확인 → ④에서 규격 위반 위험"
3. `STATE.md` 게이트 표에 `조건부통과`와 미확인 목록, 그리고 **해소 기한**을 적었다

**해소 기한의 기본값은 ④report 진입 전이다.** 특히 제출 규격·분량·양식은 ④에서 산출물 형태를 결정하므로 그전에 반드시 확정돼야 한다. IP·중복출품은 ②에서 아이디어를 고르기 전에 사용자가 알아야 한다 — 조건이 불리하면 아이디어 선택 자체가 달라진다.

사용자가 "모르니까 그냥 진행해"라고 하면 진행하되, STATE.md에 **무엇을 모른 채 진행하는지와 그것이 막혔을 때의 결과**를 기록한다.

> **ai-nativeness는 이 게이트를 면제한다.** 주제·제출규격이 현장에서 나오므로 `[현장 확정]`으로 두고 통과시킨다. 대신 대회명·일정·트랙·심사방식은 채운다.

## 5. 마무리

1. `STATE.md`를 `assets/STATE.template.md`로 생성하고 `current_stage: ②ideate`로 갱신.
2. `~/contests/INDEX.md`에 행을 추가(또는 갱신). D-day 계산.
3. 사용자에게 보고:
   - 유형 판정과 그 근거 한 줄
   - 심사표 요약 (항목·배점, 추정 표시). 심사 단계가 둘 이상이면 어느 배점으로 ②를 채점할지도 함께
   - `[미확인]` 잔여 목록 — **두 종류를 나눠서.** `미탐색`은 내가 할 일, `자료에 없음`은 사용자가 물어볼 일
   - `자료에 없음`이 있으면 **`assets/inquiry-template.md`로 만든 문의문 전문**을 바로 제시 (복사해 보낼 수 있는 형태로)
   - 다음 단계 안내

**ai-nativeness로 판정된 경우** — 여기까지는 정상 수행한다(경량 brief + rubric + STATE + INDEX 행). 그 다음 ②를 건너뛴다고 안내하고, `current_stage: ③mvp`로 두고 **대기 상태로 종료**한다. 현장에서 과제 문장을 받으면 `/contest-forge <slug>`로 재진입해 `references/3-mvp.md` §4로 들어간다.
